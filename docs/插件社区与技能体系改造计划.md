# NHY 插件社区与技能体系改造计划

> 状态：实施中
> 目标版本：NHY v0.9.0
> 最后更新：2026-11-21

## 背景

当前 NHY 的插件全部放在主仓库 `plugins/` 下，没有插件清单、版本、权限、市场或独立发布流程；技能层不存在；照片/表情包描述被截断到 30/60 字且视觉调用只有 `max_tokens=160`，会造成数据丢失；辉夜会重复同一句话或同一动作，根因包括近期想法回灌、每条想法都新建近重复记忆、动作层 `has_app_action` 让每轮必问、素材发送没有硬去重；ZCode/dsh 只有未接线参考代码；一键安装没有内部 git。

本次改造把 NHY 分成“核心框架 + 独立插件仓库 + 分级技能 + 可自建插件”四层，并保留现有使用体验。

## 用户决策

- 7 个现有插件拆分后，先本地生成完整独立仓库与发布脚本；验证完成后直接在当前 GitHub 账号创建公开仓库并推送，不再逐次询问。后续插件修改在各自远程仓库进行。
- 技能采用分级授权：只读技能启用后自动可用；写入、执行命令、安装插件等危险权限需要面板确认并写审计日志。
- B站视频分析默认最低画质，可在面板申请更高画质；大小有阈值，超过直接返回“视频过大”。技能设置和问询只放在插件面板，不进入日常认知提示词。
- 辉夜通过 harness 自建插件后自行决定并安装，不做人工审核，但必须是插件形式；通过控制面板“导入本地插件”进入指定插件目录，插件页显示详情，并提供一键重启按钮。

## 总体架构

### 1. 插件契约

新增 `plugin.json`：

```json
{
  "id": "desktop",
  "name": "电脑",
  "version": "1.0.0",
  "api_version": 1,
  "min_host_version": "0.9.0",
  "kind": "app",
  "entry": "plugin.py:PLUGIN",
  "panel": "panel.py:PANEL",
  "capabilities": ["computer"],
  "platforms": ["windows"],
  "permissions": ["desktop.uia", "process.launch"],
  "description": "……",
  "readme": "README.md",
  "homepage": "https://github.com/...",
  "license": "MIT",
  "dependencies": []
}
```

- `plugins/base.py` 增加 `PLUGIN_API_VERSION = 1`。
- `plugins/registry.py` 读取清单，兼容旧插件类属性；`list_plugins()` 返回 version/author/source/readme/permissions/installed。
- 安装目录统一为 `plugins/<id>`，保持 `plugins.<id>` import 路径。
- 新增 `config/plugins.lock.json` 记录来源、版本、SHA256、安装时间。
- 核心不再跟踪插件源码；`.gitignore` 忽略 `plugins/*/`，只保留框架文件。

### 2. 内部 Git 与插件市场

- `run/install_git.ps1`：下载固定版本 Git for Windows MinGit zip，校验 SHA256，解压到 `run/lib/git`；`setup.ps1` 和 `run/启动控制面板.bat` 自动检查。
- `setup.sh` 安装/检查系统 git；`Dockerfile` 增加 git。
- 新增 `core/plugin_market.py`：
  - GitHub Search API 检索 `topic:nhy-plugin`，也可配置中央索引 URL。
  - 校验 repo 名与 manifest id、api_version、平台、README、release ZIP SHA256。
  - 安全解压，拒绝 zip-slip；staging 后子进程 import 冒烟测试；原子移动到 `plugins/<id>`。
  - 更新 lock，标记“需重启”。
- 控制面板“插件社区”页：搜索/筛选、卡片、README 预览、安装/更新/卸载、本地导入、来源与校验标记。
- README 渲染复用 `Nascence_Huiye_Server/webui/app.js` 的 `renderMarkdown`，补 URL scheme 白名单和表格支持。
- 新增 `/api/restart` 一键重启；安装/导入/更新接口默认只允许 loopback，Docker/远程必须配置 `NHY_PANEL_TOKEN`。

### 3. 技能层与权限

- 新增 `core/skill_registry.py` 和 `config/skills.json`；技能是插件的一种 `kind: "skill"`，同样走 manifest/市场安装。
- 内置技能放在 `plugins/skills`（独立 repo `nhy-plugin-skills`，默认安装）：
  - `screenshot`：抓窗口/全屏，存图并调用视觉模型；权限 `screen.capture`；必须同时满足 `desktop_allow_screenshot`。
  - `bilibili_video`：解析 BV/av/b23/URL；默认最低画质；面板设置画质、最大 MB、最大时长、帧数；超过阈值返回“视频过大”。
  - `read_media`：按 media_id 返回完整图片/表情包描述和 OCR。
  - `plugin_forge`：调用 ZCode/DeepSeek harness 生成插件。
- 权限分为只读、写入、执行、安装四级；危险权限在面板逐项确认，审计日志写 `data/test/skill_audit.jsonl`。
- 技能设置/画质询问只在面板；禁用技能不会进入动作提示词。

### 4. 媒体全量解析

- 新增 `core/media_store.py`：以内容 SHA256 为主键，保存路径、kind、message_id、sender、timestamp、caption、full_description、ocr、pack_id、emoji_id。
- `core/llm_interface.py` 增加 full 模式：`max_tokens` 默认 3000，可配 1500-4000；不再做 30/60 字截断；表情包使用专用 prompt；推理模型返回空时自动扩大预算重试。
- 短 caption 只用于记忆/动作提示；完整内容存 media_store，由 `read_media` 全量返回。
- `plugins/qq_napcat/runtime.py`：移除 `_MAX_MEDIA_DESC=3`，改为 `media_max_items` + 并发 + 总字节预算；超出记录 skipped 原因；保留 mface pack 元数据。
- `plugins/qq_desktop`：用 `has_image` 触发视觉；尽量按 Image 控件矩形裁单图；完整描述进 media_store。
- `core/asset_library.py` 迁移 v2 hash 索引；`core/action_layer.py` 对 image/sticker 做硬去重。

### 5. 修复重复

- 新增 `core/repetition.py`：`RecentOutputGuard` 在生成后、写记忆/发送前比较最近 5-8 条；近重复最多重生成一次，仍重复则跳过并换种子。
- 修复 `core/cognition.py` 的 `has_app_action=True` 逻辑：只有新媒体、笔记变化、刚说话、明确用户输入等触发才绕过 `action_spontaneous_prob`。
- 修反刍抑制：抑制当前轮种子/边；强制转向不再从同一近期想法池抽；排除最近 N 条 thought memory ID。
- `core/memory_engine.py` 为 `我想：...` 增加 `dedup=True`，调用 `semantic_dedup`（300 秒窗口）返回已有 ID。
- `core/short_term.py` 近重复合并；`core/behavior.py:_prepare_memories` 语义去重并限制自生成想法占比；CLI `generate_response()` 同样接入 guard。
- 动作层增加 `ActionGuard`：同一 `app_do`/image/sticker/开同一对话在短窗口内硬拒绝。

### 6. 自建插件

- `plugin_forge` 面板配置 `forge_backend`（zcode/dsh）、argv 模板、超时、输出上限、staging 目录。
- 生成到 `data/plugin_staging/<id>/`：`plugin.json`、`plugin.py`、`panel.py`、README、tests、requirements。
- 自动校验 manifest、语法、子进程 import、权限声明；打包 zip。
- 辉夜自行决定安装，不做人工审核；通过控制面板“导入本地插件”进入 `plugins/<id>`，插件页展示详情；一键重启生效。
- 审计日志记录生成、导入、启用。

### 7. 拆分与发布

- 新增 `tools/split_plugins.py`，生成独立仓库：
  - `nhy-plugin-qq-napcat`
  - `nhy-plugin-wechat`
  - `nhy-plugin-web`
  - `nhy-plugin-bilibili`
  - `nhy-plugin-browser`
  - `nhy-plugin-desktop`
  - `nhy-plugin-qq-desktop`
  - `nhy-plugin-skills`
- 每仓库包含 manifest、README、requirements、tests、`.github/workflows/release.yml`；tag `v*` 发布 zip + `SHA256SUMS`，仓库加 `nhy-plugin` topic。
- `qq_desktop` 通过 manifest 依赖 `desktop`；`qq_napcat`/wechat 保留 host `panel_runtime` API。
- 先本地生成验证，再直接创建 public GitHub 仓库并推送；后续插件修改在远程仓库进行。
- 核心用 `config/plugin_bootstrap.json` 固定默认插件版本；setup 首次安装默认插件；验证后从核心删除插件源码。

## 实施阶段

1. 基础层：manifest/registry/lock、内部 git、安装器、本地导入、重启、社区页骨架、README 预览。
2. 技能与媒体：技能注册/权限/审计、screenshot、bilibili_video、read_media、媒体全量存储与 asset v2。
3. 重复修复：输出 guard、动作 guard、seed/记忆/short-term/action gate。
4. 自建插件：plugin_forge、staging 导入、插件详情、重启验证。
5. 拆分发布：8 个独立仓库、CI/Release、public 推送、bootstrap、核心移除插件源码。

## 验证

- 单元：manifest 校验、zip-slip/SHA256、技能权限、重复 guard（10 条近重复只保留 1 条）、媒体 full 不截断、asset hash 迁移、B站大小阈值。
- 集成：社区页安装/更新/卸载/README；本地导入；一键重启；截图；B站默认低清与超阈值；QQ 图片/表情包完整描述与 `read_media`。
- 行为：连续运行 30-60 分钟，确认不再重复同一句话/动作；日志无旧任务/旧未读回灌。
- 分发：每个仓库 tag 发布 zip+SHA256；GitHub 搜索/安装/更新成功；8 个仓库 public 且带 topic；核心不含插件实现。
- 安全：截图开关、技能权限、安装 token、zip 校验、子进程 import 全部有负向测试。
