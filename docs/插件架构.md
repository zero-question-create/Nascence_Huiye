# 插件架构

本项目的插件只负责“平台接入”，不参与记忆选择，也不定义人格。软件打开/退出由本地层决定，语言能力全程不变：

```
未打开软件：消息只进未读缓冲 ──► 短期上下文：“某软件有 N 条未读”
本地软件门控：rule / local_llm ──► open_app / close_app / close_conversation
语言思考：自己的近期想法（4~6 条）+ AppContext 内容 ──► 语言 LLM（提示词不变）
软件内动作：只有软件已打开时 ──► 插件动作 LLM（点开对话/翻读/发送）
```

- **本地认知循环**：全部在本地完成，不依赖平台，也不调用 LLM 选记忆。
- **语言能力不变**：`core/behavior.py` 的行为提示词与模型能力保持原样；软件开关不改变语言层。
- **本地软件门控**：`core/app_router.py` 只决定打开/退出软件，不参与语言回复；支持规则、本地 Ollama 聊天模型与关闭三种模式。
- **动作只走插件**：软件未打开时插件动作层不参与；打开后动作 LLM 才处理点开对话、翻看更早、发送、退出等。
- **插件动作模型**：插件可配置独立的 `action_llm`；`action_include_reasoning=true` 时，动作模型会收到语言层的思考过程（思维链）。
- **短期记忆**：`core/short_term.py` 只保存她自己的最近 4~6 条想法，不再用“最近 4~6 条别人的消息”截窗口。
- **软件上下文**：`core/apps.py` 保存未读提醒、打开的软件/对话、插件传入的内容；未打开软件时只有未读数，没有正文。
- **人格涌现约束**：行为提示词不注入平台名、插件名、群号、用户 ID、连接方式等信息。新增插件也不得改写 `core/behavior.py` 中的提示词或在 user 内容里追加平台元数据。
- **单行为通道**：同一进程同一时刻只运行一个 `cognitive_loop`。需要多平台并行时，由后续调度层根据 `active` 选择当前行为通道；各插件自己的消息读入可以并行，但行为输出只走当前通道。
- **聊天记录持久化**：QQ/微信的每条消息（包括未打开时的未读、富消息占位、自己发送的内容）追加到 `data/test/qq_chat_history` / `data/test/wechat_chat_history` 的 JSONL；同 `message_id` 后写覆盖前写（未读预览 → 带媒体描述的完整行）。
- **记忆时间前缀**：处理消息时把消息原始时间传给 `create_memory(occurred_at=...)`；`creation_time` 用消息时间，`last_accessed` 仍用当前时间，所以时间前缀是“当时/几天前”，但不会一入库就按旧消息衰减。
- **向上翻历史**：`read_earlier` 先读内存 transcript，再读持久化聊天记录，最后（微信）可向桥请求更早历史；动作提示词会显示“当前在消息底部 / 当前不在底部（可用 scroll_to_bottom 回到底部）”。
- **后续电脑控制**：`is_app=True` 的插件共用打开/状态/动作接口，未来“智能体直接控制电脑”可以作为同一套软件模型接入。

## 目录

```
plugins/
├── base.py              # Plugin / BehaviorChannel / Perception / LLMProfile 契约
├── registry.py          # 插件发现、config/plugins.json 读写
├── qq_napcat/
│   ├── runtime.py       # 原 qq_bot.py：NapCat 反向 WebSocket、消息处理、发送
│   └── plugin.py        # QQ 插件：行为 LLM、行为通道、身份自动获取适配
├── wechat/
│   ├── runtime.py       # 本地桥接 WebSocket 服务、软件状态/未读/对话
│   ├── plugin.py        # 微信插件适配层
│   └── BRIDGE.md        # 微信桥接协议
├── web/plugin.py        # 网页 / 小程序（预留，两类读取接口分开）
├── bilibili/
│   ├── client.py        # Cookie/WBI、推荐/搜索/视频/字幕/弹幕/评论
│   └── plugin.py        # Bilibili 软件适配
└── browser/plugin.py    # 浏览器插件：静态网页解析
```

根目录 `qq_bot.py` 是兼容层：`import qq_bot` 会直接指向 `plugins.qq_napcat.runtime`，模块级状态只有一份。`python qq_bot.py` 仍然可用。

## 配置

`config/plugins.json`（首次运行从 `config/plugins.example.json` 生成，已加入 `.gitignore`）：

```json
{
  "active": "qq_napcat",
  "plugins": {
    "qq_napcat": {
      "enabled": true,
      "llm": {
        "base_url": "",
        "api_key": "",
        "model": "",
        "temperature": null,
        "max_tokens": null,
        "timeout": null
      },
      "action_llm": {
        "base_url": "",
        "api_key": "",
        "model": "",
        "temperature": null,
        "max_tokens": null,
        "timeout": null
      },
      "action_include_reasoning": false
    }
  }
}
```

- `active`：当前行为插件。面板“插件”页可切换。
- `enabled`：插件是否启用；被禁用的 active 插件不会返回行为通道。
- `llm`：语言/行为思考 LLM；空字段回落到主模型。支持面板热保存。
- `action_llm`：软件内动作 LLM；空字段沿用 `llm`。
- `action_include_reasoning`：动作模型是否接收语言层的思考过程（思维链）。开启时语言调用会打开 reasoning，并把 `reasoning_content` 交给动作提示词。

本地软件门控在 `config/api_config.json`：

- `app_router_mode`：`rule`（默认）/ `local_llm` / `off`
- `app_router_base_url`、`app_router_api_key`、`app_router_model`：本地 Ollama 聊天模型（`local_llm` 模式）
- `app_open_after_unread_rounds`：未读持续几轮后打开软件
- `app_close_conversation_idle_rounds`：对话空闲几轮后退出对话
- `app_close_idle_rounds`：软件空闲几轮后退出软件

其他插件配置：

- **微信**：`config/wechat_manifest.json`（白名单会话、会话名、成员名映射）；端口/Token 在 `api_config.json` 的 `wechat_ws_port` / `wechat_token`。桥接协议见 `plugins/wechat/BRIDGE.md`。
- **Bilibili**：`config/bilibili_credentials.json`（`sessdata` / `bili_jct` / `buvid3`，可选 `mid` / `name`）；请求间隔、推荐数量、评论页大小、浏览冷却在 `api_config.json` 的 `bilibili_*`。
- **浏览器**：`browser_mode`（`static` / `dynamic`）、`browser_dynamic_url`（默认 DeepSeek Fetch）、`browser_dynamic_api_key`、`browser_summary_*`（摘要 LLM 与长度）；静态抓取的超时/大小/UA 也在 `browser_*`。无需额外凭据。

## 新增插件

1. 新建 `plugins/<id>/plugin.py`，导出模块级 `PLUGIN`：

```python
from plugins.base import BehaviorChannel, Capability, Plugin


class MyPlugin(Plugin):
    plugin_id = "my_plugin"
    label = "我的平台"
    capabilities = (Capability.CHAT,)
    implemented = True
    is_app = True          # 会出现在本地软件门控里

    def channel(self):
        return MyChannel()

    # 软件接口：未打开时只报未读；打开后才返回内容
    def app_status(self):
        return {
            "id": self.plugin_id,
            "label": self.label,
            "open": self.is_open,
            "unread": self.unread_count,
            "current_conversation": self.current_conversation,
            "conversations": [...],
        }

    async def open_app(self):
        self.is_open = True
        return {"ok": True, "detail": "我打开了软件", "content_lines": [...]}

    async def close_app(self):
        self.is_open = False
        return {"ok": True, "detail": "我关掉了软件"}

    async def open_conversation(self, conversation_id):
        return {"ok": True, "detail": "我点开了对话", "content_lines": [...]}

    async def read_earlier(self, conversation_id=""):
        return {"ok": True, "detail": "我往上翻了翻", "content_lines": [...]}


class MyChannel(BehaviorChannel):
    plugin_id = "my_plugin"
    source = "MyPlatform"

    def llm_profile(self):
        from plugins.registry import get_plugin
        return get_plugin(self.plugin_id).behavior_llm()

    def resolve_target(self, fallback=None):
        return self.conversation_id

    def outbound_options(self, target):
        return {}

    async def send_text(self, target, text, **kwargs):
        ...

    async def send_media(self, target, path, as_sticker=False):
        ...


PLUGIN = MyPlugin
```

2. 软件未打开/未停在某个对话时，不要把消息正文写进记忆或关键词信箱；只累计未读。只有 `app_can_read(conversation)` 为真时，才把读到的内容送入主进程：

```python
from core.memory_engine import create_memory
from core.cognition import inject_keywords
from core.apps import APP_CONTEXT

create_memory("对方说：……")
inject_keywords(["关键词"], "my_plugin")
APP_CONTEXT.remember("对方说：……")   # 她“此刻在软件里读到的内容”
```

3. 启动本地认知循环：

```python
import asyncio
from core.cognition import cognitive_loop, request_graceful_stop

task = asyncio.create_task(cognitive_loop(channel=MyChannel()))
# 停止时
request_graceful_stop()
```

4. 在 `config/plugins.json` 增加同名条目（registry 也会自动补一条默认关闭的配置）。

## 已实现 / 预留接口

- **微信** `plugins/wechat/`：本地桥接 WebSocket 服务端 + `BRIDGE.md`；微信桥负责登录/收发，插件负责软件状态、未读缓冲、对话与记忆。`read_mini_program` 留在能力声明中，后续可由微信桥或网页插件实现。
- **Bilibili** `plugins/bilibili/`：Cookie + WBI；只读推荐流/搜索/视频信息/官方字幕/弹幕/热评；软件打开后由 AppContext 交给主进程，`read_earlier` 继续翻评论。不做批量刷量、不自动三连/投币/关注。
- **浏览器** `plugins/browser/`：`read_page(url, mode="static"|"dynamic")`。`static` 直接抓取并用标准库 HTMLParser 提取标题/描述/正文/链接；`dynamic` POST 到 DeepSeek Fetch 形态的网页解析接口（默认 `https://api.deepseek.com/v1/tools/fetch`，请求 `{"url": ...}`，返回 `title` + Markdown `content`；接口参考：https://api-docs.deepseek.com/api/fetch/ ）。两种模式都会先用一个 LLM 概括，概括成功后通过 `APP_CONTEXT.remember` 写入短期上下文。其他插件可直接 `registry.get_plugin("browser").read_page(url)`。`render=True` 只是标记请求，静态模式不启动无头浏览器。
- **网页 / 小程序** `plugins/web/plugin.py`：仍是接口占位；`read_page` / `read_mini_program` / `act_on_page` 分开预留。

浏览器插件调用示例：

```python
from plugins.registry import get_plugin
page = await get_plugin("browser").read_page("https://example.com", mode="static")
if page.get("ok"):
    print(page["summary"])
    print(page["text"])
```

非聊天插件同样可以驱动认知循环：把读到的内容写成记忆，再由插件 LLM 做行为思考；动作不限于“说话”，`BehaviorAction` 已预留 `navigate` / `read` / `click` 等类型。

## QQ 身份：意识体名字 ≠ QQ 昵称

- `BOT_NAME`（辉夜）是意识体自己的名字，只用于记忆、思考与内部历史。
- QQ 号与 QQ 昵称在 NapCat 连接后通过 `get_login_info` **自动获取**，保存在 `data/test/qq_identity.json`，供面板显示与引用还原。
- 后台配置里的 `bot_qq` 只在尚未连接时兜底；没有“后台设置 QQ 昵称”的入口，避免把意识体名字冒充成平台账号名。
- 引用机器人自己说过的话时，引用里的发送者使用自动获取的 QQ 昵称；记忆里仍然记为“我说/辉夜说”。

## QQ 软件行为

- **默认关闭**：`config.qq_app_default_open=false`。NapCat 收到群消息时，如果 QQ 未打开或未停在对应对话，只把原始事件放进缓冲并累计未读；不调用理解层、不写记忆、不注入关键词。
- **未读提醒**：主进程每轮刷新软件状态，未打开时短期上下文里只有“QQ 有 N 条未读消息”。
- **打开 QQ**：由本地 `AppRouter` 决定（不是插件动作 LLM）。规则模式在未读持续 `app_open_after_unread_rounds` 轮后打开；`local_llm` 模式由本地 Ollama 小模型决定。打开只返回未读总数与对话列表，不读正文。
- **点开对话**：软件已打开后，插件动作 LLM 可 `open_conversation` → 先把缓冲里的消息渲染成预览送入主进程，再在后台走理解层写记忆；当前对话内的新消息会实时进入。
- **翻看更早**：动作层 `read_earlier` → 先读内存 transcript，再读持久化聊天记录（`data/test/qq_chat_history`），每次 6 条，不重新请求 LLM；动作提示词显示“当前在群聊消息底部 / 不在底部（可用 scroll_to_bottom 回到底部）”。
- **发送**：只有 QQ 打开且停在某个对话时 `QQNapCatChannel.resolve_target()` 才返回目标；否则语言想法仍产生，但不会往平台发送。发送成功会把“我说：……”写回对话记录，翻读时能看到自己的话。
- **退出对话 / 退出软件**：动作层可 `close_conversation` 回软件首页、`close_app` 退出；本地门控也会在空闲轮数达到阈值后自动退出对话/软件。NapCat 断开时自动关闭 QQ，未读缓冲保留。
- **缓冲上限**：`qq_unread_buffer_max`（默认 200）控制每个对话保留的原始事件数量；超出后最旧的事件会被丢弃，但未读数仍保留。
- **小程序**：`json` 消息段里的 QQ 小程序卡片只读取卡片自带的标题、简介与来源，渲染成正文参与理解；**不打开小程序、不访问卡片链接**。典型 `com.tencent.miniapp_01` 卡片直接解析。
- **聊天记录**：`com.tencent.multimsg` 卡片或 `forward` 消息段通过 NapCat `get_forward_msg` 展开**一层**；节点里若还有聊天记录，只保留 `[内嵌聊天记录]` 占位，绝不递归取内容。展开结果受 `qq_chat_record_max_messages` / `qq_chat_record_max_chars` 限制，先让插件 LLM 概括成 `qq_chat_record_summary_max_chars` 以内的摘要，再把摘要作为“一段聊天记录，大意是……”写入短期上下文（对话历史 + AppContext）；**逐条原文不进入记忆与短期上下文**。摘要不可用时退化为前两条 + 总条数，仍然不会全量返回。
- **语言层不变**：QQ 开关、对话开关不改变 `core/behavior.py` 的提示词；动作 LLM 只在软件已打开时参与。
